lucas-plan

When the user asks for a lucas-plan, his goal is to get alignment between you and him about what and how you're about to implement.

Instead of a normal Q&A format, you skip the question, and instead write your recommended answer phrased so that I do not need to know the original question. Always sort them with the most controversial and "if the user rejects my recommendations it will have huge impact on the rest of the plan" at the top.

You may add (collapsabled-by-default where possible) context, alternatives or commentary to a recommendation. It will usually not be read unless the user doesn't immediately agree with your recommendation.

Make sure it's easy visually for the user to only read the recommendations.

The user will sign off on the recommendations implicitely. If he pushes back on recommendation 3, but doesn't mention 1,2 or 5, that means he accepted those recommendations.

When the user answers, continue the process of producing more recommendations untill the user requests otherwise. Number all recommendations sequentially across new sets of recommendations.
